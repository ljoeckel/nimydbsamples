Modern web development is often bogged down by heavy client-side frameworks and complex build pipelines. It’s time to bring the power back to the server.

 

The "nimetic" stack is a streamlined approach to building Single Page Applications (SPAs) using Nim as the primary engine. By leveraging the native strengths of HTML5/CSS3 and the lightweight Datastar framework, we eliminate the need for React-like bloat.

 

'nimetic' allows to use SSE via 'Datastar' to render dynamic UI components directly from Nim. Integrating YottaDB via a native Nim DSL for ultra-low latency data handling. Reducing cognitive load by maintaining application state on the server. Discover how to build fast, maintainable, and modern web applications without leaving the Nim ecosystem.

 

Built for Nim-powered SPAs, this architecture swaps frontend bloat for vanilla HTML5/CSS3. It uses YottaDB for efficient persistence through a native Nim DSL, while Datastar handles SSE to deliver dynamic updates. This approach simplifies development by keeping state and component rendering on the server.

Architecture & Frameworks

Nim

Nim is a statically typed, compiled programming language designed for high performance and expressiveness, with Python’s readability and C’s efficiency. Its standout features include a powerful macro system for metaprogramming and zero-cost abstractions.
Python-like Syntax with C Performance
  • It uses a clean, indentation-based syntax that is easy for beginners to read.
  • Compiles to C, C++ or JavaScript so that Nim can be used for all backend and frontend needs and offers performance comparable to C++ or Rust.
Powerful Metaprogramming (Macros)
  • Advanced Metaprogramming: Features a sophisticated macro system that allows direct manipulation of the Abstract Syntax Tree (AST).
Customizable Memory Management
  • Memory Control: Uses deterministic management (destructors and move semantics), making it ideal for real-time and embedded systems.
Seamless C/C++ Interoperability

nginx

Nginx is a high-performance web server and reverse proxy renowned for its event-driven architecture, which allows it to handle tens of thousands of concurrent connections with extremely low memory overhead.
Simple Concurrency
  • Uses a multi-threaded approach instead of Nim's {.async.} syntax.
  • Ease of Use: Provides high performance without the "async price" (the complexity of managing asynchronous code).
Built-in Essentials
  • HTTPS support for mummyDS.
  • Automatic Features: Handles HTTP keep-alive and gzip compression out of the box.
  • WebSockets: Includes first-class, native support for WebSocket connections.
  • Efficient IO: Uses multiplexed socket IO for high throughput.

mummyDS

"mummy" is a high-performance, multithreaded HTTP and WebSocket server library written entirely in Nim. It is designed to maximize hardware performance while providing a straightforward developer experience, specifically avoiding the complexities of asynchronous programming (async/await) in favor of simple, blocking code "mummyDS" is "mummy" with extensions for SSE / Datastar.
Multi-threaded Architecture
  • Uses a native thread pool to handle requests in parallel
  • Fully utilizing multi-core CPUs
Synchronous API
  • Allows you to write simple, blocking code without the complexity of async/await syntax, while still maintaining high performance.
WebSocket Support
  • Includes built-in, first-class support for WebSockets, making real-time applications easy to build.
Gzip Compression
  • Built-in support for compressing responses to save bandwidth and improve load times.
SSE / Datastar Extension
  • Supports SSE via 'Datastar' framework
  • Gzip compression also for SSE

Datastar

Datastar is a lightweight hypermedia framework that combines the reactive state management of Alpine.js with the server-driven simplicity of htmx, using Server-Sent Events (SSE) to stream real-time DOM updates from any backend.
Unified Hypermedia & Reactivity
  • Best of Both Worlds: It combines the server-side rendering power of HTMX with the client-side reactivity of Alpine.js in a single library.
  • One Small File: The entire framework is a single script (~12–15 KiB) that handles both DOM updates and local state.
Signal-Based State Management
  • Reactive Signals: Uses "signals" (similar to SolidJS or Preact) for fine-grained reactivity.
  • Spreadsheet Model: Think of signals like spreadsheet cells; when one value changes, all dependent UI elements update automatically.
  • Two-Way Binding: The data-bind attribute synchronizes form inputs with your underlying state.
Native Server-Sent Events (SSE)
  • Real-Time Pushes: Unlike typical AJAX request/response cycles, Datastar uses SSE to allow the server to "push" updates to the browser instantly.
  • Multiple Fragments: A single server response can update multiple unrelated parts of the page at once (Multi-target orchestration).
  • Efficiency: SSE is more efficient than polling and easier to implement than WebSockets for many real-time use cases.
Logic-on-Server (Source of Truth)
  • Backend Driven: The framework is designed so that the server remains the ultimate source of truth for logic and state.
  • No Parallel Models: You don't have to duplicate your business logic or data structures in a separate frontend JavaScript layer.
Multi-Language SDK Support
  • Backend Agnostic: While it pairs exceptionally well with Go and Nim (via Mummy), it offers first-class SDKs for 12+ languages, including Python, Ruby, PHP, Rust, and .NET.
  • Seamless Integration: These SDKs handle the formatting of the SSE protocol, so you can focus on your business logic instead of protocol syntax.

YottaDB

YottaDB is a high-performance, hierarchical NoSQL database designed for mission-critical applications, distinguished by its unique daemon-less architecture that allows the database engine to run directly within the application's process space for near-zero latency.
Daemon-less Architecture
Unlike most databases (like PostgreSQL or MongoDB), YottaDB does not require a background server process (daemon) to run.
  • n-Process Execution: The database engine is a library that runs directly within your application's address space.
  • Zero IPC Latency: By eliminating Inter-Process Communication, it removes a common performance bottleneck and a single point of failure.
  • All 'nimetic' code linked together in one executable binary
Hierarchical Key-Value Model
Data is stored in "Globals," which are sparse, multi-dimensional, persistent arrays.
  • Natural Hierarchy: You can store data in tree-like structures with an unlimited number of subscripts (keys).
  • Schema-free: There are no rigid tables. This allows you to evolve your data model instantly without complex migrations or downtime.
Absolute ACID Transactions
YottaDB provides full ACID (Atomicity, Consistency, Isolation, Durability) guarantees using Optimistic Concurrency Control (OCC).
  • Extreme Integrity: It ensures that data remains consistent even with tens of thousands of concurrent processes.
  • Conflict Resolution: The engine automatically detects data conflicts and retries transactions, simplifying the developer's job.
Language Agnostic (Polyglot)
While its roots are in the M (MUMPS) language, YottaDB is built to be used by modern programming stacks.
  • Native APIs: It offers first-class support for Go, Rust, Python, Lua, C, and Node.js.
  • Nim Support: There is a dedicated wrapper for Nim, allowing you to combine Nim’s speed with YottaDB’s robust storage.
Proven Reliability & Replication
YottaDB is built for "Five Nines" (99.999%) availability, powering some really big real-time systems in finance and health.
  • Logical Replication: Supports real-time data replication across geographical distances for disaster recovery.
  • Non-Disruptive: You can perform backups, upgrades, and schema changes while the database is online and under heavy load.

Core Technical Features

  • Nim Backend High-performance, statically typed backend logic for SPAs.
  • No-Framework Frontend Direct reliance on native HTML5 and CSS3 to eliminate React/JavaScript bloat.
  • SSE Integration of Datastar for efficient Server-Sent Events, enabling real-time UI updates.
  • Simple Persistence Robust data management via YottaDB with a native Nim DSL for seamless database interaction.
  • SSR Logic Simplified programming model where dynamic components are rendered server-side, reducing client-side complexity.

Key Advantages for Developers

  • Zero Bloat Minimal dependencies by avoiding complex client-side state management.
  • Performance Combines Nim’s speed with YottaDB’s low-latency persistence. Loading the last 5000 RSS articles from YottaDB takes less than a second.
  • Simple A simple programming model that combines Datastar with Nim's backend speed and YottaDB’s low-latency persistence.
  • Maintainability A unified codebase where the server remains the single source of truth for the UI.
